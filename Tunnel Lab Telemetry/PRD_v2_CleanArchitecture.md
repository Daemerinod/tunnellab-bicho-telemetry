# Product Requirements Document (PRD) v2.0
**Project:** TBM Supervisory Controller & Digital Twin
**Architecture:** Clean Architecture / Adapter Pattern

## 1. Objective
Refactor the current TBM telemetry server (`simulador_bicho.py`) into a production-grade **Supervisory Controller**. The system must abstract all low-level hardware (PLCs, servo motors, sensors) using the Dependency Inversion Principle, treating hardware as interchangeable "Black Box" adapters, while maintaining strict adherence to The Boring Company (TBC) safety rules and the UDD Tunnel Lab PDB.

## 2. Architectural Layers

### 2.1. Ports (Hardware Interfaces)
Create an abstract base class `IHardwareAdapter` defining the contract for any future hardware (e.g., Siemens PLC, SEW servos).
*   `read_sensors() -> dict`
*   `write_actuators(commands: dict)`
*   `check_network_health() -> bool`
*   `is_hardware_estop_triggered() -> bool`

### 2.2. Adapters (Simulated Hardware)
Implement `SimulatedHardwareAdapter(IHardwareAdapter)` for development and testing. 
*   **Responsibility:** Encapsulate mathematical white noise, 6DOF navigation state evolution (Chainage, Easting, Northing, Elevation, Roll, Pitch, Heading), and bladder sensor battery/signal degradation.

### 2.3. Core / Domain (TBM Controller & Safety Logic)
The `TBMController` class is the "brain". It receives an `IHardwareAdapter` via Dependency Injection. Its non-blocking control loop runs at 10 Hz.
*   **Safe-State Objective:** If an E-Stop is triggered, the core must immediately command zero motion (no cutterhead rotation, no propulsion) but MUST maintain low-voltage telemetry alive by continuously calling `read_sensors()` at 10 Hz.
*   **Safe Restart (TBC Rule 10.g):** Exiting an `E-STOPPED` or power-off state requires two deliberate, independent operator inputs (e.g., `reset_estop` and `arm`).
*   **Subsystem Interlocks (PDB 5.6):** The core must enforce:
    1. Cutterhead overload -> Stop cutterhead.
    2. Propulsion motor overload -> Stop propulsion.
    3. Excessive bladder pressure -> Stop inflation & trigger relief.
    4. Loss of bladder pressure -> Disable propulsion.
*   **Command Modes (PDB 6.6.2):** Manual commands must NEVER bypass critical safety interlocks.
*   **Watchdog:** Loss of `check_network_health()` for >10s triggers a Global Abort (FAULT).

### 2.4. Presentation / API (Telemetry & Competition Comms)
*   **Local Web Server:** Asynchronous HTTP server (FastAPI/Aiohttp) exposing `GET /telemetry`, `POST /command`, and `POST /api/plc/parada`.
*   **TBC Client:** A background asynchronous task that POSTs the telemetry JSON to an external competition server endpoint at a minimum rate of 0.1 Hz (TBC Rule 7).

## 3. Data Strictness (JSON Output)
The JSON emitted via `/telemetry` is the single source of truth for the Operator Station GUI. The root level MUST rigidly contain:
*   `team`, `timestamp`, `mining`, `chainage`
*   6DOF Variables: `easting`, `northing`, `elevation`, `roll`, `pitch`, `heading`
*   A nested `extra` block containing all subsystem states.
No variables from the previous simulation version should be deleted; they must simply be generated by the `SimulatedHardwareAdapter`.
